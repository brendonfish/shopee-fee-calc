# 蝦皮帳單試算

蝦皮的對帳單會列出每項費用，但不知道賣家的進貨成本、自己貼的運費和廣告費，也不會告訴賣家方案選得對不對。這個 skill 補上這三件事：

- **這單賺多少**：撥款再扣掉成本、運費、廣告，才是淨利。
- **定價前試算**：上架前算這個價格（或組合包、湊單門檻）會不會虧。
- **該不該換方案**：拿一段時間的訂單，比全部用方案一、全部用方案二各要付多少。

## 步驟

1. **先看使用者要什麼。**
   - 只問規則（例如「蝦皮手續費怎麼算」）、沒給數字：讀 `references/fee-rules.md`，用白話解說每項費用和方案怎麼選，最後問要不要拿一筆實際訂單算算看。不用跑程式。
   - 要算一筆或一批訂單：往下做。
   - 問「該不該換方案」：請使用者匯出最近一個月的訂單成 CSV（至少要有售價、數量），用批次算（步驟 3）。只給一兩筆不夠判斷，因為方案是整個賣場一起選。
   - 問「定多少錢才不虧」：用幾個候選價格各跑一次程式，列出每個價格的淨利和毛利率給使用者比較，不要只算一個價格。

2. **問清楚數字。** 一定要有：售價、商品成本。下面兩題也要問，因為影響很大：
   - 成交手續費率：每個商品分類不同，賣家中心有分類費率表。不知道就先用 5.5%，並提醒使用者去查。
   - 有沒有透過蝦皮代開發票：有的話每單多 2.5 元。

   缺這兩題時，**先用預設值算出結果，同時反問使用者**，不要停下來等。一次最多問 3 題，照「答案會讓結果差多少」排：方案（差可達每單 54 元）、成交手續費率、費率到底改了哪一項，通常比發票（每單 2.5 元）重要。沒問到的用預設值算，列在假設裡。使用者說「手續費 6%」時，確認他指的是成交手續費率，不是方案一的 6%。

   其他沒給就用預設，並在結果裡講出用了哪些假設：
   - 數量（預設 1）
   - 免運專案方案：使用者不知道的話，照平台預設算方案二，並請他到賣家中心「蝦皮活動 > 已報名」確認
   - 買家付的運費、賣家負擔的運費、賣家給的折扣（預設 0）。蝦皮券、蝦幣是蝦皮出的錢，不影響賣家被扣多少，不用算
   - 是不是促銷檔期、是不是商城、有沒有參加蝦幣回饋、是不是預購（備貨 2 個工作日以上）、廣告費、包材等其他成本（預設沒有）

3. **用程式算，不要心算。** 要給使用者看的每一個數字（包括「換成方案一會賺多少」「改費率前後差多少」）都要實際跑程式，不要自己加減推算。 程式在這份 SKILL.md 所在資料夾的 `scripts/calc.py`。「skill 資料夾」就是你讀到這份 SKILL.md 的那個資料夾（Claude Code 載入時會顯示它的路徑，Codex 會列出 SKILL.md 的位置）。工作目錄通常不是 skill 資料夾，所以**一定要用完整路徑執行**：

   ```
   python3 <這個skill資料夾的完整路徑>/scripts/calc.py --price 500 --cost 200 --commission-rate 5.5% --plan 方案一
   ```

   `python3` 不能用的話，改試 `python` 或 `py -3`（Windows 常見）。

   常用參數：`--qty`、`--buyer-shipping`、`--seller-shipping`、`--seller-discount`、`--campaign`、`--mall`、`--preorder`、`--coin-cashback 3%`、`--ad-cost`、`--other-cost`、`--no-invoice`、`--json`。費率可以填 `5.5%`、`5.5` 或 `0.055`；方案可以填 `方案一`、`方案1`、`1`、`plan1`。

   **一批訂單**（從蝦皮、Google 試算表或 Excel 下載的 CSV）分三步，**先確認欄位再計算**：

   a. 先檢查，不計算：

   ```
   python3 <skill資料夾完整路徑>/scripts/calc.py --csv <使用者的CSV路徑> --inspect
   ```

   程式會列出：每一欄被當成什麼（名稱對上、用猜的）、每欄的值會被讀成什麼（例如方案欄的「型1」讀成方案一、「1,580」讀成 1580）、哪些欄位不使用、還缺什麼。

   b. 把結果整理成一張表給使用者確認：「你的欄位 → 當成什麼 → 讀到的值」。用猜的、看不懂的、缺的要特別標出來，並問一句「這樣對嗎？」。**使用者確認之前不要計算。**使用者說哪裡不對，用參數修正後再跑一次 `--inspect` 給他看：
   - 欄位對錯：`--map '型別=方案,金額=售價,運費=忽略'`（左邊是使用者的欄位名，右邊填標準欄位名或「忽略」）
   - 方案寫法程式看不懂（例如「甲」「乙」）：問使用者各代表哪個方案，再加 `--plan-values '甲=方案一,乙=方案二'`
   - 只有「訂單金額」這類總額、沒有單價：程式會當成商品總價，用總價 ÷ 數量當單價。要問清楚這欄有沒有含運費

   不使用的欄位（姓名、電話、地址等）程式不會印出內容，你也不要另外去讀或複述。

   c. 確認後計算，帶上 `--inspect` 最後印的 `--map`（和用到的 `--plan-values`）：

   ```
   python3 <skill資料夾完整路徑>/scripts/calc.py --csv <使用者的CSV路徑> --map '<確認過的對應>' --out <使用者工作資料夾>/試算結果.csv
   ```

   - 使用者說「整批都是」的條件（例如手續費率都是 6%、都沒有代開發票），照單筆的參數加在指令後面：`--commission-rate 6% --no-invoice`。CSV 沒有那一欄、或那格空白時用這個值；CSV 有填就照 CSV。程式會印出「整批預設」，`--inspect` 時也會列出來，一起給使用者確認。
   - 輸出檔一定要存到使用者拿得到的地方，不要存進 skill 資料夾（可能是唯讀的）。在 Claude 網頁版或 App，存到 `/mnt/user-data/outputs/` 再交給使用者；在 Claude Code 或 Codex，存到使用者的專案資料夾。輸出檔不能跟輸入檔同名。
   - CSV 第一列是標題，可用：售價、數量、成本、買家運費、賣家運費、賣家折扣、成交手續費率、方案、檔期、商城、預購、蝦幣回饋、廣告費、其他成本、開發票。只有「售價」是必填。是否類欄位填 是／否。
   - 金額有千分位、NT$、百分比格式、全形數字、Big5 編碼都讀得懂。程式加的欄位都以「試算_」開頭，不會蓋掉原本的欄位。某一列格式錯，只有那列在「試算_狀態」標「錯誤」、「試算_提醒」寫原因，其他列照算。兩個標題對到同一個欄位（例如同時有「售價」和「單價」）時，問使用者要用哪一欄，另一欄用 `--map` 填「忽略」。欄位名稱不必完全一樣，程式會先猜，但猜的結果一定要經過步驟 a、b 讓使用者確認。空白列會照樣保留，貼回原表不會錯位。

   程式回報「輸入有問題」時，把訊息用白話轉告使用者，請他確認數字，不要自己猜一個值硬算。

   不能執行程式的環境，照 `references/fee-rules.md` 的規則手算，每項費用各自四捨五入到元。

   **使用者自己的費率**（蝦皮改了費率、這個 skill 還沒出新版時用）：

   費率有三層，後面的蓋前面的：內建 `references/fees.json` → 使用者的 `shopee-fees.json` → 這次的 `--set`。`shopee-fees.json` 寫什麼就照什麼算，不分訂單日期。

   | 情況 | 怎麼做 |
   | --- | --- |
   | 使用者給了費率檔（上傳的、或專案資料夾裡的 `shopee-fees.json`） | `--fees <檔案路徑>`。在 Claude Code 或 Codex，工作資料夾裡有 `shopee-fees.json` 會自動用，不必加參數 |
   | 使用者說了新費率，但還沒確認清楚（哪一項、哪些付款方式） | 用 `--set` 先試算，例如 `--set payment_fee_rate=3%`，**不要建檔**，同時問清楚 |
   | 確認清楚了 | 在使用者的工作資料夾（不是 skill 資料夾）建或改 `shopee-fees.json` |
   | 要跟內建費率比較（改前改後差多少） | 再跑一次加 `--builtin`，這次不套用 `shopee-fees.json`（也不要加 `--set`） |

   `shopee-fees.json` 的寫法：**只寫要改的欄位**，費率填小數。欄位名稱照 `references/fees.json`，巢狀的照原本的層級寫，沒寫的照內建。`fees_as_of` 填蝦皮公告的日期，只是記錄，不影響計算；不用提醒使用者生效日前後的訂單要分開算：

   ```json
   {"payment_fee_rate": 0.03, "shipping_program": {"plan2_fixed": 70}, "fees_as_of": "2026-11-01"}
   ```

   - 使用者已經有這個檔，就在原本的內容上改，不要整個覆蓋。原本的內容不是這次使用者說的，回報時列出來請他確認還對不對（批次時 `--inspect` 會印出「用了使用者費率」，放進確認表）。
   - `--set` 的欄位名稱一樣，巢狀的用點分層：`--set shipping_program.plan2_fixed=70`。費率可以寫 `3%` 或 `0.03`。
   - 使用者說「信用卡費率」「刷卡手續費」：對應的是 `payment_fee_rate`（金流服務費，蝦皮叫金流與系統處理費），但這個費率同時套用在信用卡、貨到付款、街口支付。
     - 還沒確認是不是只有信用卡時，可以用 `--set` 先試算，但要明講「這是假設所有付款方式都改」。
     - 確認只有信用卡改的話，**不要寫進 `shopee-fees.json`**：程式分不開付款方式，寫進去會讓貨到付款、街口的訂單也多算。照實跟使用者說，結果只能當刷卡訂單的參考。
   - 在 Claude 網頁版或 App：把 `shopee-fees.json` 建在執行程式的資料夾（程式才會自動讀到），再複製一份到 `/mnt/user-data/outputs/` 給使用者下載。跟他說這次的修改只在這段對話有效，下次開新對話把檔案上傳就好。
   - 想讓使用者知道改了多少：一般跑一次、加 `--builtin` 再跑一次，列出每單差多少。主要結果用使用者問的那個（通常是新費率），另一個放後面當比較。

   欄位名稱打錯或數字不合理，程式會報錯，照訊息修正，不要繞過。

4. **用白話回報。** 依序講：
   - 撥款實拿多少、淨利多少、毛利率
   - 每一項被扣多少（表格）
   - 方案一和方案二這單各要多少，哪個便宜。並提醒：整個賣場只能選一個方案，要看全部訂單，不是每單各選
   - 批次算的時候，程式最後會印整批合計和「方案建議」。照實轉告：全部用方案一、全部用方案二各要多少，現在的方案多付多少，以及訂單金額落在哪幾段。方案 30 天內可以換一次
   - 程式給的提醒（虧錢、毛利太低、選錯方案、用了哪些假設）
   - 程式印出「用了使用者費率」時，一定照實講出改了哪些費率（例如「金流服務費率 2.5% → 3%」），讓使用者知道這次不是用內建費率算的。印出「照內建費率算，沒有套用」時，也要講出來
   - 程式只印檔名，不印完整路徑；轉告時也不要寫出使用者電腦或伺服器上的完整路徑

5. **最後一定附一句：** 費率版本是幾月幾日的資料，蝦皮會改規則，請到蝦皮賣家中心核對。程式印的「費率版本」是內建費率的日期；有用使用者費率時，兩個分開講（例如「內建 2026-09-08，金流服務費用你給的 3%」）。

## 注意

- 規則依蝦皮賣家中心官方公告（`references/fee-rules.md` 有來源和官方範例）。費率和打平點都從 `references/fees.json` 算出來，蝦皮改規則時只改這個檔，不改程式。使用者要用自己的費率，用 `shopee-fees.json` 疊上去，不要改 skill 資料夾裡的檔案（可能是唯讀的，下次更新也會被蓋掉）。
- 要跟別人的試算文章比對時，條件要設成一樣（成交手續費率、有沒有發票費、有沒有蝦幣回饋、運費和廣告費算不算），不然數字會差幾元。
- 只做試算，不登入蝦皮、不改任何設定。
- 這是給老闆看的管理帳，不是報稅用的帳。
